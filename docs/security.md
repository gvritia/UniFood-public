# Безопасность UniFood

Документ к пункту 23 практического занятия: защита приложения и данных.

## Реализованные меры

| Область | Мера |
| --- | --- |
| Вход | Пароли хешируются bcrypt; JWT подписывается HS256 и имеет срок действия. Ключ загружается из окружения и должен быть случайным, длиной не менее 32 байт. |
| Права доступа | Операции администратора проверяют роль на сервере. Пользовательские заказы и позиции корзины проверяют владельца. Регистрация и редактирование собственного профиля не могут назначать роль администратора. |
| Ввод | Pydantic проверяет цены, количества, суммы и длины строк. Явное `null` для обязательных полей при обновлении отклоняется до обращения к БД. |
| Фото блюд | Принимаются JPEG, PNG и WebP до 5 МБ. Формат определяется по сигнатуре содержимого; имя отправителя не используется для пути сохранения. Старый файл удаляется только после успешного обновления записи. |
| Ошибки | Ответы и журналы ошибок валидации не содержат исходные значения полей, включая пароль. |
| Браузер | Nginx задаёт CSP, `nosniff`, запрет встраивания страницы и политику Referrer. CSP разрешает шрифты Google и изображения по HTTPS, а запросы API — с того же источника. |
| Доступ к сервисам | PostgreSQL доступен только контейнерам сети Compose; опубликованные порты frontend и backend привязаны к `127.0.0.1`. `.env` исключён из Git. |

## Проверки

- `python -m unittest discover -s tests -p test_authorization.py` из папки `backend`: проверки регистрации, ролей, владельца корзины, статусов заказа, валидации и загрузки фото.
- `python -m pip_audit -r backend/requirements.txt`: аудит Python-зависимостей.
- `npm audit` из `frontend/unifood-frontend`: аудит JavaScript-зависимостей.
- `docker compose up --build -d`: сборка и запуск сервисов; затем проверка `/health`, `/api/menu/` и защитных заголовков ответа Nginx.

На 7 ноября 2026 года аудит текущих файлов зависимостей не нашёл известных уязвимостей. Проверку следует повторять при изменении версий.

## Границы текущего решения

Проект рассчитан на локальную демонстрацию. При размещении в интернете нужны HTTPS, политика ограничения частоты попыток входа и отдельное решение для хранения токена вместо `localStorage`. Пополнение баланса и гостевая оплата остаются демонстрационными. Если frontend будет обращаться к API на другом домене, следует явно добавить этот домен в `connect-src` CSP и настроить CORS backend.
