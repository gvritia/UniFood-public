# Кэширование и производительность (пункт 24)

## Публичное меню

`GET /menu/` хранит готовые ответы в памяти процесса backend 30 секунд. Ключ включает `skip`, `limit`, `category` и `q`; кэш ограничен 128 вариантами запроса. В заголовке `X-Menu-Cache` видны `MISS` при чтении из PostgreSQL и `HIT` при повторном запросе. Пустое меню тоже кэшируется. После создания, изменения, удаления блюда или загрузки его фото кэш очищается после успешного коммита.

В Docker Compose backend работает одним процессом. При ручном изменении БД вне API или запуске нескольких процессов записи могут оставаться устаревшими не более 30 секунд. Для нескольких реплик понадобится общий кэш (например, Redis) или отказ от кэша процесса.

Выдача меню упорядочена по `id`, чтобы страницы не менялись местами между запросами. `skip` не может быть отрицательным, `limit` находится в диапазоне 1–100. Это ограничивает размер одного ответа.

## Запросы к БД и загрузка страниц

- История и административный список заказов загружают позиции, блюда и пользователей пакетно через `selectinload`, вместо отдельных запросов для каждой строки. Тест с пятью заказами ограничивает выдачу истории пятью `SELECT` с учётом авторизации.
- Гостевой заказ получает все нужные блюда одним запросом и затем проверяет каждую позицию по полученной таблице.
- React загружает код страниц по маршруту. Карточки меню откладывают загрузку изображений до появления на экране; фильтр и поиск вычисляются из исходного списка без дополнительного обновления состояния. Поиск позиций корзины выполняется через `Map`.

## Проверка

После запуска `docker compose up --build -d` дважды выполните `curl.exe -i http://localhost:8080/api/menu/`. Первый ответ должен содержать `X-Menu-Cache: MISS`, второй — `X-Menu-Cache: HIT`. Через 30 секунд следующий ответ снова будет `MISS`. Изменение блюда через API также сразу приводит к `MISS`.

Автоматические проверки: из корня проекта запустите `python -m unittest discover -s backend/tests -p test_*.py` с `PYTHONPATH=backend` и `npm run build` в `frontend/unifood-frontend`.
