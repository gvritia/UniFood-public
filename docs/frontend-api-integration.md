# Интеграция фронтенда с API

Документ к пункту 22 практического занятия. React-приложение обращается к FastAPI через общий Axios-клиент в `frontend/unifood-frontend/src/api/axios.js`.

## Адрес API

По умолчанию клиент использует `/api`. При разработке Vite перенаправляет этот путь на `http://localhost:8001`, а в Docker Compose Nginx отправляет его в контейнер backend. Поэтому страницы работают с одним и тем же адресом API в обоих режимах. Если backend расположен отдельно, адрес можно задать через `VITE_API_URL` при сборке фронтенда.

## Сценарии обмена данными

| Сценарий | Запросы | Как обновляется интерфейс |
| --- | --- | --- |
| Каталог | `GET /menu/` | Блюда показываются после загрузки; при ошибке есть повторный запрос |
| Регистрация и вход | `POST /users/`, `POST /auth/login`, `GET /auth/me` | Ответ входа сохраняет JWT и пользователя; при перезагрузке данные сверяются с сервером |
| Корзина | `GET/POST /cart/`, `PATCH/DELETE /cart/{id}` | После изменения позиции клиент заново получает серверную корзину и сумму |
| Оформление | `POST /orders/`, затем `GET /cart/` и `GET /auth/me` | Сервер создаёт заказ и очищает корзину; клиент обновляет корзину и баланс и открывает историю |
| История | `GET /orders/` | Показывает заказы, пустое состояние или ошибку с повторной загрузкой |
| Профиль | `GET/PUT /profile/me`, `POST /profile/balance` | Данные профиля и баланс обновляются после ответа сервера |
| Администрирование | `/admin/*`, `/users/{id}`, `/menu/*` | Администратор загружает статистику и списки, меняет роли, статусы и меню; фото отправляется через общий API-клиент |

Axios-клиент добавляет JWT в заголовок `Authorization: Bearer ...`. Защищённые маршруты ждут завершения проверки токена через `/auth/me`. При смене email фронтенд завершает сеанс и предлагает войти с новым адресом, поскольку текущий JWT содержит прежний email. Состояние корзины очищается при выходе или смене пользователя, а запоздавший ответ прежнего запроса не заменяет данные нового сеанса.

Ошибки API бывают строкой `detail` или массивом ошибок валидации. Функция `getApiErrorMessage` преобразует оба формата в текст для интерфейса. При сбое загрузки корзины и заказов пользователь видит ошибку и может повторить запрос; ошибка не маскируется под пустой список.

## Проверка вручную

1. Открыть `/menu` без входа и убедиться, что меню загружается через `/api/menu/`.
2. Зарегистрироваться и войти, затем обновить страницу: `/auth/me` восстанавливает пользователя.
3. Добавить блюдо в корзину, изменить количество и оформить заказ: корзина пустеет, заказ появляется в истории, баланс меняется.
4. Изменить email в профиле: приложение переводит на вход с новым адресом.
5. Войти администратором, изменить блюдо или роль и загрузить фото: запросы выполняются с JWT через общий клиент.
